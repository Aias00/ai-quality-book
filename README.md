16 章正文、前言与 4 个附录（含自动生成的完整实验代码）。围绕版本化样本、任务验收、评分校准、逐样本差异、项目配对统计、预算、争议和发布门槛，回答“候选变了以后，凭什么允许发布”。

## 全书内容

1. 先写发布决定，再选择指标
2. 评测集首先是一份数据合同
3. 训练、开发与验收要按真实关联切分
4. 任务完成与回答质量分别验收
5. 先证明评分器不会轻易被骗
6. 把候选执行与验收证据隔开
7. 总分之外，保留每个任务的配对变化
8. 配对统计与区间不能替代样本设计
9. 预算不足不能让困难任务消失
10. 人工争议需要留下可以追溯的决定
11. 分别改变提示、检索与生成器
12. 把发布门槛变成可失败的程序
13. 运行完整质量流水线
14. 让错误评分、争议与预算在实验中显形
15. 接入真实模型之前，还缺哪些证据
16. 把评测维护成产品能力

## 运行实验

Python 3.10+，仅标准库，不需要外网、模型密钥或供应商SDK：

```sh
python3 -m unittest discover -s tests -v
python3 -m lab.demo
```

26个合成样本按项目切为训练资料6条、开发8条、验收12条。文件修改任务核对真实产物，知识回答核对结构化事实及引用。候选在临时子进程中执行，父进程持有答案与评分器；这只是合作式输入分离，不是OS沙箱。

三个受控比较分别得到修复通过、检索回归拒绝、生成缺陷拒绝。完整报告、失败样本、评分器校准和项目bootstrap区间保存在 `lab/evidence/`。17项测试覆盖数据指纹/切分、产物与表达分离、错误引用、预算和超时、评分误判、人工裁决、配对统计及CI失败退出。

## 结果范围

没有训练或调用真实模型，没有测量真实人类一致率，没有供应商排名。`prompt_v2`是确定性请求归一化替身，`model_v2`是控制的生成器缺陷；它们不是真实模型评测。最低表达合同不衡量任意自然语言语义或文采。

6个合成验收项目上的统计只用于演示计算与门槛，不能证明真实业务总体改善。公开题不构成未曝光验收集。候选同OS身份、无敌对代码沙箱；预算是输入/输出JSON字节单位，不是token或货币。审查身份是自声明教学字段，不是认证授权。
